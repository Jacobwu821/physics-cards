# 任务：把本地已完成的「物理卡片」应用部署到 GitHub Pages，并配置 GitHub 私有仓库同步

## 背景（已完成，不要重做）

本地目录 `E:\PhysicsCards` 是一个已经开发、测试完成的 Web 应用（React + TypeScript + Vite，中文界面），git 仓库已初始化，`main` 分支上有 2 次提交，工作区干净。功能：物理学习记忆卡片，Markdown + LaTeX（KaTeX）混排，FSRS 间隔复习，随机抽卡，备份恢复，离线应用壳（Service Worker），多设备同步。

与部署相关的既有事实：

- 前端在 `app/`，构建命令 `npm run build --workspace app`，产物在 `app/dist/`。构建已配置为相对路径（`base: './'`）和 hash 路由，可直接放在 `https://<用户名>.github.io/<仓库名>/` 这样的子路径下。
- `.github/workflows/pages.yml` 已写好：推送 `main` 时自动 `npm ci` → `npm test` → 构建 → 用 `actions/deploy-pages` 部署。需要仓库的 Pages Source 设为 **GitHub Actions**。
- 测试：`npm test`（59 项，全部通过）。Node 版本要求 ≥ 22.13（工作流用 Node 24，服务端测试依赖 `node:sqlite`）。
- 同步有两种后端，用户将使用「GitHub 私有仓库」后端：应用通过 GitHub Contents API 读写私有仓库中的 `sync/data.json` 和 `sync/images/*`，需要一个只对该私有仓库有 **Contents: Read and write** 权限的 fine-grained 令牌。令牌由用户在应用的「设置 → 同步」页面填写，只存在浏览器里，**不要写进任何仓库或代码**。
- `README.md` 里「零服务器方案」一节有完整步骤，可参考。

## 要做的事

1. **创建公开仓库并推送代码**
   - 在用户的 GitHub 账号下创建公开仓库 `physics-cards`（免费账号只有公开仓库能用 Pages；仓库内只有代码，不含用户数据）。不要用任何初始化文件（不要自动生成 README、.gitignore、license），避免与本地历史冲突。
   - 在 `E:\PhysicsCards` 执行：
     ```
     git remote add origin https://github.com/<用户名>/physics-cards.git
     git push -u origin main
     ```
   - 如果本机 git 推送需要凭据而你无法提供，改用你已接入的 GitHub 权限完成推送（例如通过 API 或 gh CLI）。不要改写提交历史。

2. **启用 GitHub Pages（Source = GitHub Actions）**
   - 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。用 API 的话：`POST /repos/<用户名>/physics-cards/pages`，body `{"build_type":"workflow"}`（若已存在则 `PUT` 同一路径）。
   - 到 Actions 页面确认 "Deploy to GitHub Pages" 工作流成功。若失败，读日志修复（最常见：Pages 未启用、Node 版本不对、`npm ci` 找不到 `package-lock.json`——它在仓库根目录，是 npm workspaces 结构）。

3. **创建私有数据仓库**
   - 创建**私有**仓库 `physics-cards-data`，勾选 "Add a README"（为了直接有 `main` 分支）。里面不需要放任何东西，应用会自己创建 `sync/data.json`。

4. **令牌**（如果你的权限做不了这一步，就把下面步骤原样告诉用户让他手动做）
   - GitHub 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
   - Repository access：Only select repositories → 只选 `physics-cards-data`。
   - Permissions → Repository permissions → Contents → **Read and write**。其余不要给。
   - 把令牌交给用户，让用户在应用「设置 → 同步」中选「GitHub 私有仓库」，填 `<用户名>/physics-cards-data`、令牌、分支 `main`，点「测试连接」再「保存设置」。**你自己不要把令牌写进仓库、Issue、代码或提交信息。**

5. **验证部署（必须做）**
   - 打开 `https://<用户名>.github.io/physics-cards/`：页面出现「今日」「牌组」「卡片库」「设置」导航，无 404，浏览器控制台无报错。
   - 进入「设置」：「出门使用 / 离线」面板应显示「离线缓存已就绪」（说明 Service Worker 在 https 下注册成功）。
   - 「设置 → 示例数据 → 载入示例数据」，然后打开「卡片库」：卡片里的公式应显示为排版后的公式（分数、上下标、希腊字母），**不能**出现原始的 `$...$` 或 `\frac` 源码；若出现源码或红色文字，说明 KaTeX 资源没有正确加载，检查 Pages 子路径下的静态资源是否 404。
   - 若用户已填好令牌：点「立即同步」，状态应变为「已同步」，且私有仓库 `physics-cards-data` 中出现 `sync/data.json`。

## 约束

- 不要修改应用代码、构建配置或工作流，除非部署确实失败且原因明确；改动要最小，并说明原因。
- 不要创建除上述两个仓库之外的仓库，不要改仓库可见性（代码仓库公开、数据仓库私有）。
- 不要把任何令牌、密码写入文件或提交。
- 最后向用户报告：两个仓库地址、Pages 网址、Actions 运行结果、验证清单各项是否通过、未能完成的项及原因。
